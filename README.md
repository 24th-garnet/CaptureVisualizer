# CaptureVisualizer

iPhone / iPad の LiDAR で撮った室内スキャンを、手元のブラウザで確認するツール。

スキャン（`.mdr` バンドル）を置いたディレクトリを指すと、一覧・平面図・3D が
ブラウザで開き、家具を動かして 3D に反映できる。

```bash
uv run mdr2colmap web ~/scans        # http://127.0.0.1:8765/
```

<!-- 画面: 左に一覧、中央に平面図、右に頂点カラーの 3D -->

## できること

- **一覧** — 撮影日・枚数・面数・未撮影率。RoomPlan の有無や配置の保存をタグで示す
- **平面図** — `room.json` があればそれを、無ければメッシュから起こす
- **3D** — 撮影直後に焼いた頂点カラーのメッシュ。裏面を透過するので外から中が見える
- **家具の移動** — 平面図でドラッグすると 3D が同時に動く。結果は `moves.json` に
  書き出し、`arrange` が実際のメッシュを切り分けて動かす

平面図と 3D は**同じ座標系**に載せてある（主方向で回し、原点は図面の左上、床が
Y=0、単位はメートル）。そのため同期は引き算だけで済み、位置合わせの処理を持たない。

## 動かす

Python 3.11 以降と [uv](https://docs.astral.sh/uv/)。

```bash
uv sync
uv run mdr2colmap web <バンドルを置いたディレクトリ>
```

外部依存は numpy / scipy / pillow だけ。サーバは標準ライブラリの `http.server`
で、単一利用者の手元道具として足りる。3D の描画は three.js を CDN から読む。

`localhost` 以外へ開くときは合言葉が要る（省略すると自動生成して起動時に表示）。
閲覧だけ配るなら `--read-only` で書き込みを止められる。

```bash
uv run mdr2colmap web ~/scans --host 0.0.0.0 --read-only
```

Web アプリ以外に、同じパッケージへ入っている道具:

```bash
uv run mdr2colmap verify    room-xxxx.mdr               # 座標変換とポーズの検証
uv run mdr2colmap roomplan  room-xxxx.mdr -o plan/      # RoomPlan から平面図
uv run mdr2colmap floorplan room-xxxx.mdr -o plan/      # メッシュから平面図（旧データ用）
uv run mdr2colmap arrange   room-xxxx.mdr --moves m.json -o out/   # 家具を切り分けて動かす
uv run mdr2colmap texture   room-xxxx.mdr -o out/       # Mac 側でテクスチャを焼き直す
```

## モジュール

| | 役割 |
|---|---|
| `mdr.py` | バンドルの読み込み。ポーズ・深度・信頼度・EXIF |
| `coords.py` | ARKit ↔ OpenCV の座標変換。**変換規約はここに集約する** |
| `mesh.py` | メッシュの PLY 読み込み |
| `roomplan.py` | `room.json` の読み込み。壁・ドア・窓・家具 |
| `meshplan.py` | メッシュから平面を起こす（内部を面として塗る） |
| `floorplan.py` | メッシュから壁を推定（Manhattan 前提、開口部は検出できない） |
| `segment.py` | RoomPlan の箱で家具を切り分け、動かす |
| `webapp.py` | HTTP サーバ。平面図の生成・編集の保存・DXF |
| `webgeom.py` | ブラウザへ渡す 3D。部品への切り分けと間引き |
| `dxf.py` | 平面図を DXF R12 で書き出す |
| `texture.py` | テクスチャ焼き込み。iOS 実装（Metal）の参照実装 |
| `verify.py` | 再投影による座標変換の検証 |
| `pointcloud.py` | 深度の非投影。`verify` と `photometric` が使う |
| `photometric.py` | フレーム間の露出差を揃える。**テクスチャ経路での効果は未確定** |

## 平面図の編集

**編集後を正とする。** 壁を動かした時点で図面は実測ではなくなるが、それを承知で
編集結果を成果物にする。元データは触らないので、いつでもスキャン直後へ戻せる。

| | |
|---|---|
| 角を掴む | そこに集まる壁がすべて追従する |
| 壁を掴む | 法線方向にだけ動く。長さと向きは変わらない |
| 壁を押す | 動かさずに離すと選択。長さと開口の数が出る |
| 内法 W / D | 数値で入れると遠い側の辺が引っ張られる |
| 壁を追加 | 2 点を指す。既存の角の 25cm 以内なら吸い付く |
| 壁を削除 | 選んで削除。開口と**撮った面**も一緒に消える |
| 刻み | 50mm |
| 保存先 | `plan_edit.json`。`room.json` は書き換えない |
| 戻す | 「スキャン直後に戻す」で `plan_edit.json` を消すだけ |

壁を掴んだときに法線方向へ限るのは、自由に動かすと長さと向きが同時に変わり、
部屋の寸法を直すつもりの操作で角度まで狂うため。

**開口は壁の a 端からの距離を保つ。** 実務では開口の位置は壁の端からの実寸で
決まるので、壁が伸び縮みしても距離は動かさない。壁が縮んで収まらなくなった
ときだけ端へ寄せる（消さずに残し、人が直せるようにする）。

本格的な編集は CAD へ渡してから行う想定で、ここは部屋サイズの調整までを持つ。

## 編集を 3D に映す

編集した壁を直方体に起こし、スキャンの上へ半透明で重ねる。**スキャンは変形
しない。** 測ったものと描いたものを別の物として見せる。

変形させない理由は 2 つ。変形したメッシュはもう実測ではないこと。そして壁の
追加と削除は対応する面がスキャンに無いので変形では映せないこと。図面から立体
を起こせば、追加も削除もそのまま出る。

実測した 1 室では直方体 10 個 / 三角形 120 枚で、スキャン本体（42,352 面）の
0.28%。壁を掴んでいる間も毎フレーム作り直して差し支えない。

開口は腰壁と垂れ壁だけ残す（RoomPlan の `sill` と `h`）。扉は開いて描かない
——開き勝手が出ないのは平面図と同じ理由。

スキャンした壁も一緒に動く。**家具とまったく同じ扱い**で、壁を別の部品に切り出し
て剛体で動かす。部品は自分だけの頂点を持つので、動かしても床や天井を引き伸ばさ
ず、継ぎ目はそのまま開く。開いた先は撮れていないので色も付かない——それが実測の
限界で、引き伸ばして繕うと測っていない面を描くことになる。

| | 実測（1 室） |
|---|---|
| 振り分けの精度 | wall 99.4% / window 100% / door 100% が壁線の 0.25m 以内 |
| 部品 | 壁 4 枚で 24,909 面。部屋（床・天井）17,443 面 |
| 開く領域 | 壁 1 枚を 0.5m 動かすと床側 1.57 m² + 天井側 1.57 m² |

面の振り分けは `mesh_class.bin`（ARKit の面分類）を使う。分類が `none` でも、
立っていて壁の近くにあれば壁として扱う——壁の近くの `none` 面の 48.7% が立って
おり、落とすと壁に穴が開く。

**壁にしか繋がっていない突出物は壁と一緒に動く。** エアコン・配管・柱・窓台の
ように、壁にだけ付いている物は壁が動けば一緒に動くのが自然。面の隣接を辿って
拾い、床・天井・家具（`table` / `seat` の分類）で止める。高さでも止める——分類が
`none` の床・天井面が 23% あり、分類だけでは止まらない。届く距離は壁線から 0.6m。

**RoomPlan が箱を持つ物は、壁に接していても動かさない。** 位置は人が平面図で
決めるもので、壁から決まるものではない。

**写すのは線分ではなく線。** 端点に合わせると、角のドラッグで端だけが動いたとき
に壁が自分の向きのまま滑る（実測で w3 を 0.5m 動かすと隣の w1 が 0.5m 滑り、w0
の端は 0.49m 潰れた）。原点を「元の a を新しい線へ下ろした足」に取ると、線が動い
ていない壁の変換は恒等になる。

### 撮れていない隙間を塞ぐ

**メッシュそのものに穴がある。** 実測で床の被覆は 68.8%、天井 98.4%、壁は 76.5〜
95.0%。三角形が無いので、アトラスをいくら埋めても背景が透けて黒く見える。

平面図は「そこに床と壁がある」と言っているので、その形で面を起こしてスキャンの
**裏側**に置く。撮れたところはスキャンが手前に出て、撮れていないところだけこの面
が見える。

| | |
|---|---|
| 色 | 床・天井・壁それぞれの**中央値**（サーバで測る。平均だと撮り残しの縁の暗さに引きずられる） |
| 床 | Y = −0.02（スキャンの床は +0.0155m） |
| 天井 | 天井高 +0.02 |
| 壁 | 壁線から室外へ 0.08m（スキャンした面は線から 1〜43mm 内側） |

色は模様を持たない一色にする。**測っていない場所に模様を描かない**ための区別で、
のっぺりしていること自体が「ここは撮れていない」の表示になる。

床と天井は平面図の外形いっぱいの矩形で足りる。壁の外へはみ出すぶんは、同時に
起こす壁の面が室内から隠すので、凹んだ形の部屋でも三角形分割が要らない。

面の向きは巻き方向を手で決めず、法線を計算して合わせる。裏返っても黙って通る
ため。

### 編集で残る破片

**二種類あり、原因が違う。**

**元から浮いている小片** — 間引き後のメッシュは連結成分が 115 個あり、本物の面
（床 10.04 / 天井 7.77 / 壁 5.90〜7.74 / 家具 1.46〜4.81 m²）と小片の間に 6 倍の
段差がある。0.02 m² 未満の成分を落とす（89 成分 / 408 面 / 0.234 m²）。0.1〜0.25
m² には椅子の脚（0.242 m²）のような本物が混じるので、そこは残す。

**編集後の部屋の外に残る面** — こちらは編集量に比例する。壁を 0.3m 内側へ動かす
と床・天井が 1.71 m²、直交する壁の突き出しが 1.15 m² 取り残される。大きな連結
成分の一部なので、小片を落とす処理では消せない。

動いた壁ごとに半空間で切る。部屋の外形を多角形に組み直さないので、壁を足して
ループが閉じていなくても破綻しない。実測で 0.3m の移動なら 1,160 面 / 1.29 m²、
0.5m なら 3,069 面 / 3.61 m² を隠す。

- **境界は壁線ではなく壁の外面**（線から壁厚ぶん外）。壁線で切ると壁そのものが
  消える（試すと 67,854 面中 22,444 面が消えた）
- 壁の区間の外は切らない。L 字の部屋で延長線が室内を切らないため
- その壁自身の部品は切らない。壁の実体は自分の線より外にある
- 家具は切らない

室内がどちら側かは**床の面がある側**で測る。巻き方向には頼らない——RoomPlan の
壁は法線が室内を向くが、メッシュ由来の平面図や人が足した壁ではその保証が無い。

**図面から消した壁は、撮った面も消える。** 消えるのは表示だけで、元の形は部品の
中に残っているから、取り消しでそのまま戻る。元データ（`mesh_vc.glb`）には触れない。
「壁を動かす」を切れば、測ったままを見たいという意味なので消した壁も出る。

家具は壁に追従しない。壁を内側へ動かせば家具を貫くが、それは「そこまで動かした」
という事実の表示で、隠すと編集の結果が見えなくなる。家具は平面図で掴んで直す。

## 中を歩く

「歩く」で一人称に切り替わる。W A S D / 矢印で移動、マウスで見回す、Esc で戻る
（[FloorplanStudio](https://github.com/24th-garnet/FloorplanStudio) の walkthrough
を下敷きにしている）。平面図には立ち位置と向きが出る。

| | |
|---|---|
| 目の高さ | 1.6 m |
| 歩く速さ | 1.4 m/秒 |
| 体の半径 | 0.3 m |
| 登れる段差 | 0.4 m |
| 当たりを見る高さ | 0.35 / 1.0 / 1.45 m |

**当たり判定は平面図に対して行う。メッシュには当てない。** three.js の
Raycaster は BVH を持たず総当たりなので、面数がそのまま効く——実測で 1 フレーム
7 本の光線に 67,446 面で 13.81ms、167,281 面なら 33.58ms かかり、テクスチャ版に
すると歩けなくなる。平面図なら壁 4 枚と家具 4 個の計 8 個で済み、**0.20 µs**。

速いだけでなく確かでもある。床は 67.7% しか撮れておらず（ベッドの下は 7%）、
メッシュに当てると穴を抜ける。床の高さは Y=0 で固定する（`webgeom` が揃えており、
実測でスキャンの床面は +0.0155m、標準偏差 0.0225）。

代わりに、平面図に無いもの（突き出したエアコン、段差）は止めない。段差のある家や
複数階も歩けない。

軸ごとに分けて進む。まとめて止めると壁に沿って滑れず、角で動けなくなる。

図面から消した壁は通り抜けられるので、編集した結果の中を歩ける。

## CAD へ渡す

「DXF」で書き出す。**R12（AC1009）のテキスト形式**を手で組む——外部依存が要らず、
どの CAD でも読めるため。単位はミリメートル、向きは画面と同じ（X = 平面図の z、
Y = 平面図の x）。編集後の壁と、動かした家具の位置がそのまま入る。

| レイヤ | 中身 |
|---|---|
| `A-WALL` | 壁の断面（閉じたポリライン） |
| `A-OPNG` | 窓・出入口 |
| `A-FURN` | 家具の外形と名称・W×D×H |
| `A-DIMS` | 内法の全体寸法 |
| `A-ANNO` | 室名 |

レイヤ名を ASCII にしてあるのは、**R12 にレイヤ名の文字コードの定めが無く**
日本語名が読み手の環境で化けるため。文字列は `$DWGCODEPAGE` に `ANSI_932` と
宣言して cp932 で書く。寸法は `DIMENSION` ではなく線と文字で組む——R12 の
`DIMENSION` は寸法スタイル表と結びついていて、手で組むと読み手によって
見え方が変わる。

## 平面図の作り方

**`room.json`（RoomPlan）があるとき** — 壁・開口・家具の箱をそのまま使う。

**無いとき** — メッシュだけから起こす（`meshplan.py`）。壁を線として拾うのではなく
**内部を面として塗る**ので、床が家具に隠れていても天井が見えていれば面積が欠けない。

**2 経路の差は開口部に出る。** 同じ部屋での実測:

| | RoomPlan | メッシュ |
|---|---|---|
| 必要なもの | `room.json`（撮影時に同時取得） | `mesh.ply` のみ |
| 内法 | 3.14 × 3.60 m | 3.05 × 3.60 m |
| 面積 | 11.29 m² | 11.0 m² |
| 壁 | 4 枚 | 4 枚 |
| **ドア** | **3 枚（幅つき）** | **0 枚** |
| 家具 | 4 個 | なし |

寸法は 3cm 以内で一致する。メッシュ経路の開口部検出は「壁面の鉛直被覆の欠落」を
探す発見的な手法なので、**ドアが閉まっていると壁と区別できない**。ドアと窓のない
平面図は不動産の資料にならないので、`room.json` の無い旧データ向けと割り切る。

RoomPlan を持つ 5 バンドル（同一の部屋）で答え合わせした結果:

| | メッシュ | RoomPlan | 差 | 天井被覆 |
|---|---|---|---|---|
| A | 11.34 | 11.36 | −0.1% | 10.91 |
| B | 11.16 | 11.25 | −0.8% | 10.69 |
| C | 11.34 | 11.44 | −0.9% | 11.00 |
| D | 11.01 | 11.21 | −1.8% | 10.80 |
| E | 9.32 | 11.29 | **−17.4%** | **7.25** ← 撮り残し |

天井が撮れていれば −0.1〜−1.8%。外れた 1 件は天井被覆が面積に対して足りず、
`MeshPlan.reliable` が `False` を返すので**焼いた後に自動で分かる**。

5 件はすべて同じ部屋なので、これは「1 室を 5 回撮った再現性」であって 5 室での
一般性ではない。

## 描画の方針

平面図は**平面表示記号だけ**を描く。壁は平行 2 本線、窓一般、出入口一般。

**確かめていないものは描かない。** 扉の開き勝手は描かない——RoomPlan は寸法しか
返さず、メッシュを測っても閉じた扉は板厚ぶん（12〜17mm）が均一に出るだけで、
把手のような手がかりが無い。方位記号も描かない——屋内では磁気コンパスが実測で
20 度以上ずれる。

## 3D

**テクスチャで描く。** `mesh.glb`（4096² のアトラス付き）を家具と壁ごとに切り
分けて間引く。面積あたりの色の数が頂点カラーの **235 倍**になる。

| | 色の間隔 |
|---|---|
| 頂点カラー（間引き後） | 40.5 mm |
| テクスチャ | **2.64 mm/texel** |

アトラスに 2.64mm の実体があることは確かめてある。1/2 に落として戻すと 31.0 dB
——JPEG 品質 90 の劣化（38〜40 dB）より大きく失われる。

**位置だけで間引くと壊れる。** アトラスのチャートの継ぎ目をまたいで UV が平均
され、テクスチャがちぎれる。UV も鍵に入れてまとめる。その代わり頂点が継ぎ目で
割れるので、**小片を落とすときの繋がりは位置で見る**——頂点番号のまま数えると
成分が 30 個から 5,196 個に増え、本物の面を 13.6%（7.86 m²）消してしまう。

`mesh.glb` は `mesh_vc.glb` と**面の並びが違う**（面数 167,281・面積 60.134 m²
は同じでも重心の差が中央値 1.0m）。`mesh_class.bin` は `mesh.ply` の並びに紐づく
ので、位置と重心で引き直してから使う。

### 黒い領域を埋める

アトラスの **25.2% が真っ黒**。内訳は、チャートの中に閉じた穴（撮れていない面）
が 3.22%、残り 21.7% がチャート外の隙間。

**埋めるのは穴だけ。** 歩いて見えるのはそこだけで、隙間は三角形が参照しない。
隙間を黒のまま残しても縮小表示で困らない——撮影アプリの膨張がチャートの縁から
中央値 31 texel（約 83mm）伸びており、黒が滲むのは mip 4 段目（texel 42mm）より
粗いところだけ。

**バイキュービックでは届かない。** 補間は既知の点のあいだしか埋められず、穴は
縁から最大 38 texel（約 100mm）奥まっている。ピラミッドへ畳んでから戻す
**push-pull** で埋める（実測 2.5 秒、`.web/atlas.jpg` にキャッシュ）。

色は近傍からしか来ない。各 texel は「自分の升目に値がある一番細かい段」から取る
ので、穴の周りに色があればそこで決まる。段を 64 texel で打ち切っても結果が変わら
ないことを確かめた（差の中央値 0.0）。

1×1 まで畳む。2×2 で止めると、その升目が空のとき埋め残る。拡大は float のまま
行う——uint8 を経由すると暗い穴が 0 へ張り付いた（埋め残し 0.497% → 0.139%、
残りは「まわりが暗い穴」であって埋め残しではない）。

**既知の texel は変えない**（埋める前の段階で差の最大 0）。JPEG で入れ直すぶんは
動くので品質を 95 にし、差の中央値を 0 に抑えた。3.67MB → 3.63MB。

**埋めた色は測った値ではない。** まわりの平均が滑らかに伸びているだけで、模様は
作らない。見ていない場所に模様を描くより、のっぺりしているほうが「ここは撮れて
いない」と分かる。

アトラスは base64 で混ぜず別に配る（3.5MB が 4.7MB に膨らむうえ、画像として別に
取ればキャッシュに乗る）。実測で geom 3.69MB + アトラス 3.67MB。

サーバ側の焼き直し（`texture`、177.7 秒）は採らない。texel は細かくなるが
（2.31mm / 埋まり 68.6%）**ぼける**——鮮鋭度 474 対 808、1/2 で 33.5 dB 対
31.0 dB。複数視点を混ぜるぶん高周波が失われる。

RoomPlan の向き付き境界箱を線で重ねる。**箱の向きはサーバ側で平面図と同じ枠へ
落としてから渡す**ので、ブラウザ側は中心に置いて回すだけでよい。

移動は平面図からのみ。3D で掴めるようにすると、移動量が「掴んだ点と床面の交点」
で決まるため視点によって変わり、平面図の数値と食い違う。

## 家具の切り分け

RoomPlan は家具を向き付き境界箱で返すので、箱の中の面を選べば分離できる。実測
（`room-33d49373` / 148,897 面）:

```
収納 13,852 / テーブル 6,445 / 椅子 1,245 / ベッド 5,405
部屋 121,950   床付近で除外 13,742
合計 148,897 = 元と一致
```

切り出した部品の実寸は宣言寸法と 2〜10% 以内で一致する。**床から 4cm 以内の面は
家具に含めない。** RoomPlan の箱は床面から始まるので、そのまま切ると椅子を動かし
たときに床が付いてくる。

## 動かすと見えるもの

家具をずらすと、**撮れていない場所**が露わになる。

- **床の穴** — 家具の足元は撮れていない。実測でベッドの足元は 19%、テーブルは 95%
- **壁側の開いた殻** — 壁に付いていた面は一度も写っていない

これは道具の限界ではなく撮影の限界で、直すには床面の穴埋めが要る。

## バンドルの形

```
room-xxxxxxxx.mdr/
  manifest.json     機種・映像/深度の形式・枚数・撮影秒
  poses.jsonl       1 行 1 フレーム。姿勢・内部パラメータ・露出・シャープネス
  frames/           JPEG と深度（float16）と信頼度
  mesh.ply          world 座標のメッシュ
  mesh_class.bin    面ごとの ARKit 分類（1 面 1 バイト）
  mesh_vc.glb       頂点カラー付き
  room.json         RoomPlan の壁・開口・家具（撮影時に同居させた場合）
  bake.json         焼き込みの内訳と品質
```

パッケージ名が `mdr2colmap` なのは、COLMAP への変換から始まった経緯による。

## 来歴

もとは Mac 側で 3D Gaussian Splatting（3DGS）まで通す構想だったが、**計算資源を増やして
も品質が上がらない**と実測で分かったため畳んだ。

| 施策 | 数値 | 盲検の目視 |
|---|---|---|
| 解像度 480 → 1920 | ±0.18 dB（反復分散と同程度） | 区別できず |
| ガウシアン 50 万 → 100 万 | +0.44 dB | 区別できず |
| 露出補正 | +1.64 dB | 有意に良い |

解像度が効かない理由も特定した。**入力画像に 480 を超える情報がない。** 480 に
落として戻しても原寸に対し 39.2 dB。露光 1/100 秒のあいだにカメラが約 10 画素
動いており、実効解像度は 200 画素相当しかない。

そのとき削ったもの: COLMAP 書き出し、初期点群の構築、ポーズ精密化、station 抽出、
TSDF 再融合、パノラマ合成、splat ビューア。座標変換だけ `coords.py` に残した。

いまは**撮影が端末上で完結する**（焼き込み 1.41 秒 / 167,281 面）。このツールは
その出力を受け取って、平面図・編集・3D・CAD への受け渡しを担う。
